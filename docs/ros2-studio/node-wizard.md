# New ROS Node wizard (M12)

Open a local ROS workspace in Zed, then choose **Create node** in ROS Graph, right-click empty graph grid and choose **New ROS Node**, or run `ros_studio::CreateNode` from the command palette. Enter a ROS node name and select a Rust package. The wizard detects the `rclrs` version from the package's `Cargo.toml` (0.6 or 0.7) and selects the matching executor API. If no `rclrs` dependency exists, Auto uses 0.7. For a dependency without an explicit version, choose 0.6 or 0.7 manually; the wizard does not rewrite an existing `rclrs` dependency. A manual choice that conflicts with an explicit version, or an explicit version outside 0.6–0.7, is rejected. The wizard shows the new `src/bin/<name>.rs` source and the exact `Cargo.toml` content before writing either file. It adds the selected `rclrs` version and `anyhow = "1.0"` only when the package does not already declare them. After creation, Zed rescans the graph and opens the generated source.

The wizard turns spaces into underscores while the name is entered and ignores hyphens, punctuation, non-ASCII characters, and leading digits. It accepts only a new ASCII ROS node name. It refuses to overwrite an existing source file or a manifest that changed after preview. It does not edit existing source code. Python and C++ node generation, publisher/subscription code generation, and choosing existing topics are outside M12 and belong to later milestones.

To try it in the demo workspace, select the `camera` package and use a fresh name such as `camera_backup`. The generated binary needs a sourced ROS 2 environment to compile, such as the existing ROS Humble development container. A newly generated node has no publishers or subscriptions until you add them. Do not use the example workspace for permanent application code; remove only the generated demo files you created when finished testing.
